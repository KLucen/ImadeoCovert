## 1. 建议与范围

沿用 Python + Tkinter 桌面架构，图片继续使用现有 Pillow 转换链路，视频新增 FFmpeg 子进程转换链路，使用 FFprobe 读取媒体信息。保留本地处理、拖放、批量转换、深浅主题和多语言的产品方向。

首版按 Windows x64、离线使用、通用 SDR 视频转换设计。图片与视频使用两个模式，分别保存文件列表和转换参数。第一阶段只允许一个批次执行，避免图片线程池与视频编码器同时争用资源。

### 接入视频之前需要处理的限制

1. **入口和模型依赖图片。** `_drop()` 使用 `IMG_EXTS`，`_load_resolutions()` 使用图片探测，`_start()` 与 `_convert_worker()` 直接依赖图片参数。视频不能只通过增加扩展名接入。
2. **停止不是中断。** `_toggle_stop()` 设置共享布尔值，工作线程在一个文件完成后检查；`shutdown(wait=False, cancel_futures=True)` 不会终止已经运行的转换。视频必须有自己的取消事件与进程句柄。
3. **并发策略不适用于视频。** 图片最多同时处理 8 个文件；单个 FFmpeg 编码器本身可能使用多个 CPU 线程。视频默认串行，后续再开放可配置并发。
4. **进度与结果粒度不足。** 目前进度以完成文件数计算，结果在批次收尾时按输入顺序统一插入。视频需要单文件进度和即时完成事件。
5. **文件对应关系需要稳定 ID。** 现有列表、排序和比较较多依赖位置关系。视频任务使用 `task_id` 关联输入、进度和结果，避免排序或失败后错配。
6. **缓存不能直接照搬。** 现有缓存检查路径、配置及输出存在性，未纳入源文件大小和修改时间。首版视频不启用跨任务结果跳过，后续再引入可验证缓存。
7. **临时文件提交需改进。** 图片代码先 `os.remove(out_path)` 再 `os.replace()`；后者失败时旧文件已经丢失。视频采用同目录唯一临时文件，验证成功后直接替换，不预删旧结果；禁止覆盖任何当前批次的源文件。
8. **错误详情需要贯通。** `convert_one()` 返回 `error_msg`，现有工作线程的结果事件没有传递它。新增任务结果应包含可展示错误及诊断日志。
9. **说明与源码有差异。** README 提到文件夹拖放，但当前 `_drop()` 未实现目录递归。视频首版承诺文件批量导入，文件夹扫描作为独立增强项。
10. **fork 发布身份尚未完成。** 程序名称、版本链接、更新 API、README 下载地址和产物名仍使用 Formatix／上游地址。发布前集中调整，同时保留原作者署名与许可证。

## 3. 首版功能定义

### 输入与输出

输入选择器支持 `.mp4`、`.mov`、`.mkv`、`.avi`、`.webm`、`.m4v`、`.wmv`、`.flv`、`.ts`、`.mts`、`.m2ts`；扩展名只用于筛选，最终由 FFprobe 验证文件与流，实际支持范围取决于捆绑 FFmpeg 的解码器。

| 输出预设 | 视频编码 | 音频编码 | 定位 |
| --- | --- | --- | --- |
| MP4，默认 | H.264 / libx264 | AAC | 日常播放和分享 |
| MKV | H.264 / libx264 | AAC | 通用 Matroska 输出 |
| WebM | VP9 / libvpx-vp9 | Opus / libopus | WebM 输出 |

采用明确的“容器 + 视频编码 + 音频编码”预设，避免把 MP4 与 H.264 当成同一层级的格式。引擎必须检测实际编码器与复用器能力；缺少必要能力时禁用对应预设并说明原因。

### 用户操作

- 顶部切换“图片 / 视频”；各自保留列表和参数，转换中锁定模式切换及本批次参数。
- 添加或拖入多个视频，后台读取时长、分辨率、帧率、编码、大小与音轨信息。
- 选择格式、输出目录、画质档位、编码速度；支持保持原分辨率或等比例缩小至 1080p / 720p，不默认放大。
- 默认保持源时间特征，不强制改为 30fps；高级帧率转换放到后续阶段。
- 默认选择主视频流与默认音轨，保留声音；可切换静音。无音轨输入仍可正常转换。
- 显示当前文件进度、处理速度、估算剩余时间、已完成/总文件数；转换结束立即更新对应结果。
- 支持取消当前任务并停止队列、查看错误、重试失败项、打开结果和输出文件夹。

首版不承诺多音轨、字幕或附件完整保留；导入时识别，并在输出摘要中明确轨道取舍。主视频选择应排除封面图流，不能直接假设第一个视频流就是正片。

首版不提供 HDR/Dolby Vision 到 SDR 的自动转换，也不声称保留所有 HDR 或透明通道。检测到这些输入时给出明确的不支持状态；后续在完成色彩、元数据和编码测试后开放。普通手机竖屏、旋转元数据与可变帧率应列入首版验证范围。

### 后续增强

- 无损换封装：只在容器与所选流兼容时使用 stream copy；用户选择该模式后，不能静默回退成有损转码。
- MOV 输出、H.265 / AV1、NVENC / QSV / AMF 硬件编码与实机能力探测。
- 目标文件大小、两遍编码、帧率控制、片段裁剪、音频导出、GIF。
- 多音轨和字幕选择、HDR 转换、视频帧比较、文件夹递归导入。
- 混合媒体队列、任务历史与恢复。暂停/恢复需要另行定义可靠行为，不纳入首版。

## 4. 技术设计

```text
Tkinter App：模式切换、输入输出列表、参数、状态
  ├─ 图片转换入口 → 现有 converter.py / Pillow
  └─ 视频面板 → VideoOptions / MediaTask
                  ↓
             TaskRunner
               ├─ FFprobe → MediaInfo
               └─ FFmpeg  → 临时文件 → 结果验证 → 正式文件
                  ↓
             queue.Queue 中的任务事件
                  ↓
          App.after() 在主线程更新界面
```

### 模块边界

| 模块 | 计划职责 |
| --- | --- |
| `media_models.py` | `MediaInfo`、`VideoOptions`、`MediaTask`、`ConversionResult`、进度事件数据类 |
| `ffmpeg_service.py` | 定位 FFmpeg/FFprobe、版本和能力检查、媒体探测、进程启动/退出及日志 |
| `video_converter.py` | 预设验证、参数构造、转码、进度解析、取消和输出验证 |
| `task_runner.py` | 批次和任务生命周期、每批独立取消事件、串行队列、事件投递 |
| `video_panel.py` | 视频参数区域和媒体信息展示，降低主窗口新增代码量 |
| `file_utils.py` | 从图片模块抽取纯命名/大小工具，增加路径冲突与临时文件管理 |
| `app_metadata.py` | 产品名称、版本、仓库和发布地址的单一来源 |

先让新视频链路闭环，再决定是否迁移图片调度至通用 TaskRunner。避免为了新增视频一次性重写现有主窗口与图片处理。

### 媒体探测

使用 FFprobe JSON 输出，例如 `-v error -show_format -show_streams -of json`。解析视频流、音轨、时长、分辨率、帧率有理数、旋转、像素格式及色彩标记；处理 `N/A`、缺失时长和无有效视频流。探测在后台运行，有超时和取消机制。

FFmpeg 与 FFprobe 必须来自同一发布包。默认优先使用捆绑引擎；允许用户显式配置工具目录；开发环境可回退 PATH。检测缺失时只禁用视频能力，图片仍可使用。引擎发现基于应用或模块路径，不能依赖进程当前工作目录。

### 执行与进度

- 使用标准库 `subprocess.Popen`，参数数组、`shell=False`；Windows 使用无控制台窗口的进程创建选项。
- 首版采用 `-nostdin`，取消通过持有的进程句柄执行 terminate、限时等待、必要时 kill，并回收进程和管道。采用这一策略时不能再依赖 stdin 输入 `q` 退出。
- 以 `-progress pipe:1 -nostats` 获取结构化进度，stderr 单独持续消费并保留有界诊断日志，避免管道写满死锁。
- 以输出时间与媒体时长估算当前进度；总时长未知时展示已处理时间和活动状态。整体进度可按时长加权，但需标注为估算。
- 进度达到结尾不等于成功：进程正常退出、输出探测通过并提交文件后，才标记 100% 和成功。
- 所有事件带 `batch_id` 和 `task_id`；取消、清空、关闭窗口后的旧事件不可修改新任务状态。UI 事件限频，避免频繁进度消息淹没主线程。
- 每个批次使用独立 `threading.Event`，不能用一个共享布尔值跨越停止和重新开始。

任务状态：`queued → probing → running → validating → succeeded`，另有 `failed`、`cancelling → cancelled`。每个任务只有一个终态；单文件失败不阻断其余文件，初始化失败则给出批次错误。

### 编码参数

- 默认 MP4 使用 libx264、AAC、兼容的 8-bit 像素格式及 faststart；速度与画质分别控制，不把速度档位解释为画质。
- 画质档位分别映射到 H.264 与 VP9 的编码参数，不把图片 0–100 质量百分比原样传递到视频。
- 保持宽高比，兼顾旋转后显示方向与像素宽高比；需要偶数尺寸的编码路径显式调整尺寸，调整策略在输出信息中可见。
- 显式映射选定视频与音轨；静音模式显式去除音频。输出音轨编码与容器预设一致。
- HDR/高位深/透明内容需明确检测与处理策略，不通过简单指定 `yuv420p` 假装完成可靠色彩转换。

### 文件安全、错误与缓存

- 规范化并比较输入/输出路径，禁止覆盖当前批次的任一输入；同名文件预分配互不冲突的输出名，按 Windows 大小写规则处理冲突。
- 输出目录内创建唯一临时文件，例如 `name.<task_id>.part.mp4`，保留合法容器扩展名或显式指定 `-f`，不能直接沿用图片的 `.tmp` 推断方式。
- 只有退出码成功且 FFprobe 确认流、尺寸、时长等基本属性符合预期，才提交结果。覆盖批准的旧结果时直接 `os.replace()`；默认无覆盖路径还需在提交阶段检查竞争，不可无条件覆盖突然出现的文件。
- 取消或失败只清理本任务的临时文件；保留既有输出。对磁盘空间不足、权限、编码器缺失、损坏文件给出可理解的错误与详情。
- 关闭窗口时终止并回收本应用启动的视频进程，不能留下孤立 FFmpeg。首版不自动恢复未完成临时文件。
- 后续缓存键至少包含源绝对路径、大小、纳秒修改时间、完整转换参数和引擎标识；命中时检查输出有效性。需要更强一致性时再增加内容校验。

## 5. 界面与设置接入

复用主窗口两栏结构：左侧源文件，右侧结果；在视频模式增加时长、编码、状态/进度等列。视频参数区独立构建，图片比较按钮仅在图片模式可用，视频提供“打开播放”。文件选择、拖放和格式筛选使用一致的校验入口。

设置建议采用版本化结构：`schema_version`、`general`、`image`、`video`。产品配置文件使用独立的 ImadeoCovert 路径；首次启动可读取旧 Formatix 设置进行一次迁移，保留原文件，避免两个应用互相覆盖配置。关闭“记住设置”时，需要一致地处理图片和视频参数。

品牌名称暂按仓库名 ImadeoCovert 处理；正式展示名称可以独立确定。发布地址改为 `KLucen/ImadeoCovert`，无发布版本时更新检查正常降级；不移除原作者版权声明。

## 6. 打包与发布

1. 新增运行及开发依赖清单并锁定已验证版本，开发依赖包含 pytest 和 PyInstaller；本阶段不随意升级 Python 基线。
2. 新增 PyInstaller spec。首选便携目录 + ZIP：主程序、`tools/ffmpeg.exe`、`tools/ffprobe.exe`、资源和许可证一起分发，减少大型引擎在单文件模式下反复解包的启动成本。若仍需单 EXE，可作为后续单独测量和验证的产物。
3. 固定 Windows FFmpeg 构建版本、来源、SHA-256 和构建配置；构建中获取并验证，运行时无需联网下载。对实际捆绑构建验证 H.264/AAC、VP9/Opus 等能力。
4. 保留项目原许可证；按实际 FFmpeg 构建包含相应许可、来源及所需源码获取材料。FFmpeg 的许可取决于编译配置，不能一概写成 LGPL；使用 libx264 的构建需要特别核对其 GPL 配置。发布前逐项核对分发材料。
5. CI 增加参数/探测解析/生命周期测试与真实短视频转换测试，再构建、运行产物冒烟测试并上传 ZIP。手动构建与标签发布区分，普通验证不得误发版本。
6. README 增加视频支持矩阵、引擎版本、文件体积说明、首版限制及故障排查，修正指向上游的下载地址。

### 首版必需验收用例

- 含声音与无声音视频分别导出 MP4/MKV/WebM；探测实际容器/编码，并通过播放检查音画同步。
- 批量包含正常与损坏输入：坏文件有明确错误，其余任务继续；结果始终与源任务对应。
- 中文、空格、括号、Unicode 和较长路径，同名不同目录输入，源与输出目录相同。
- 单个长视频显示持续进度；时长未知输入不显示虚构百分比。
- 运行中取消、清空、再次开始、关闭窗口：没有残留进程、旧事件干扰或误报成功；本地正常负载下以 3 秒内完成取消作为目标验证。
- 转码失败、磁盘写入失败、目标被占用或替换失败：旧输出和全部源文件保持完整，临时文件可清理。
- 竖屏/旋转、非方形像素、奇数尺寸、可变帧率；多音轨/字幕输入的取舍可见；HDR 输入按首版策略明确拦截。
- 缺失 FFmpeg 或编码器时视频功能提供具体诊断，图片功能仍可使用。
- 图片的 PNG/JPEG/WebP、可用的 HEIC/AVIF/SVG、缩放、命名、比较、设置、主题和语言回归。
- 在未安装 Python、未设置 FFmpeg PATH、断网的 Windows x64 环境中验证完整 ZIP 产物。

测试分三层：纯参数与解析单元测试、真实 FFmpeg 小样本集成测试、Windows GUI/打包验收。样本尽量通过测试脚本生成，真实手机样本使用获准使用的素材；大视频不直接提交仓库。
