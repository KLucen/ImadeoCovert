# P2 桌面视频界面与验收

日期：2026-10-26。基线：P1 提交 `1a4a5b4`，已推送至 GitHub 的 `feat/video-conversion-core`。P2 在独立开发分支实施，开发版本标记为 `1.18.0-dev`，不代表已发布便携程序。

## 启动与使用

沿用已经创建的 Anaconda 环境，不创建 uv 环境，不增加第三方 Python 依赖：

```powershell
conda activate imadeo-p0
python formatix.py
```

1. 在顶部切换“图片 / 视频”。两种模式分别保留文件列表和参数；任务运行期间锁定模式和转换参数。
2. 视频页自动在后台检查 FFmpeg / FFprobe。可选择自定义引擎目录，或恢复“内置 / PATH”。错误只影响视频功能；可点引擎旁的“详情”查看路径、版本和缺失的编码器。
3. 点击“添加视频”或拖入文件。两种入口使用相同过滤规则，支持 `.mp4/.mov/.mkv/.avi/.webm/.m4v/.wmv/.flv/.ts/.mts/.m2ts`，去重并忽略目录及其他扩展名，不递归导入目录。
4. 列表显示时长、显示尺寸、帧率、视频编码和大小。选中行可查看音轨数量和 HDR、透明、高位深、额外轨道提示；“详情”提供完整说明和诊断日志。
5. 选择 MP4 / MKV / WebM、画质、编码速度、最大高度（原始 / 1080 / 720）、是否移除音频及输出目录。预设随引擎实际能力过滤；静音时不要求音频编码器。
6. 点击“转换视频”。显示当前任务进度、速度、预计剩余时间及批次成功/失败/取消计数。只有验证并提交输出文件后才显示成功和 100%。未知时长显示已处理时间。
7. “取消”终止当前视频进程并将未开始任务标记为取消；“清空”先取消并等待后台线程退出，再清理列表。任务真正退出前不能启动另一批。
8. 修复问题或调整参数后，点击“重试失败 / 已取消”。新批次拥有独立取消事件与批次 ID，已成功项保留。双击已完成的结果，或选中后点击“打开 / 播放”，调用系统关联播放器；也可打开输出文件夹。

默认保留已有文件，同名输出自动编号。GUI 不提供覆盖开关。视频仍沿用 P1 的安全临时文件、输出验证和提交逻辑。

## 设置与产品身份

- 新配置：`~/.imadeocovert_settings.json`，结构为 `schema_version: 1`、`general`、`image`、`video`。
- 仅在新文件不存在时读取旧 `~/.formatix_image_converter_settings.json`；旧文件始终保留，下一次保存时写入新文件。
- 临时文件与目标设置文件位于同一目录，通过 `os.replace()` 原子替换。损坏或未知版本的配置会提示并保留，不自动覆盖。
- 关闭“记住设置”同时清除磁盘中的图片和视频参数；语言、主题、更新检查和引擎目录仍保留。文件队列和任务结果不写入配置。
- 新视频控件提供中文和英文，其他现有语言使用英文回退；切换语言不改变预设的内部值。深浅主题沿用原应用，重启生效。
- `app_metadata.py` 统一名称、开发版本、仓库和发布地址；应用名称为 ImadeoCovert，更新检查指向 `KLucen/ImadeoCovert`，无 Release 时正常降级。保留上游版权、许可和作者署名。

## 实现与生命周期

`video_panel.py` 负责 Tk 界面、稳定行 ID 和事件展示，`video_session.py` 负责后台引擎检查、媒体探测及串行批次。后台线程只写队列；Tk 主线程每 75 毫秒消费最多 100 个事件，根据批次和任务 ID 更新对应行，旧批次事件被忽略。

操作完成事件和线程退出均确认后才解锁。关闭窗口先设置取消事件，以 `after()` 非阻塞等待视频进程被回收，再销毁窗口。图片取消也会等待已开始的图片写入完成；等待发生在工作线程，窗口可继续响应。图片功能保留原转换逻辑和比较窗口。

后台更新检查原有的跨线程 `after()` 调用也改为队列消息，关闭窗口后不会再从该线程调用 Tk。

## 验证

测试环境：Windows、Anaconda `imadeo-p0`、Python 3.10.22、固定版本 FFmpeg 9.0.2 essentials。全量命令：

最终结果：**121 passed，0 skipped，60.50 秒**；`pip check` 报告 `No broken requirements found`。测试报告：`test-results/p2-tests.xml`。这是一轮本地验收结果，P2 尚未作为发行版发布。

```powershell
$env:IMADEO_REQUIRE_FFMPEG='1'
conda run --no-capture-output -n imadeo-p0 python -m pytest -q --junitxml=test-results/p2-tests.xml
conda run --no-capture-output -n imadeo-p0 python -m pip check
```

验收覆盖：

- 真实 GUI 导入、探测、转换、混合成功/失败、修复后重试、打开结果路径及两种模式隔离。
- WebM 编码中清空、阻止抢先重启、新批次 ID 和取消事件隔离、旧事件丢弃。
- 编码中关闭窗口，检查启动的子进程均退出、临时文件被清理。
- 引擎缺失和恢复、编码能力过滤及静音例外、图片实际转换和取消后的模式锁。
- 中文/英文切换、其他语言回退、深浅主题、最小 1150×640 窗口的底部控件可见性。
- 旧配置迁移、不记忆设置的一致性、损坏/未知配置保留、原子保存失败时旧文件不变。
- P0 图片与媒体探测、P1 参数、文件保护和真实转换回归。

本机实窗检查已执行：中文视频页完成 640×360、24 fps、带音轨 MP4 转换，结果大小、分辨率和 100% 状态正确；修复了初次检查发现的底部进度区域被挤出的问题。GUI 测试按真实应用的“一进程一个根窗口”运行，每个案例使用独立子进程，避免 Windows Tcl / 原生 tkdnd 在同一进程反复加载和销毁时的初始化问题；超时也会暴露未退出的后台线程。

测试报告位于被 Git 忽略的 `test-results/`。P1 分支推送时原工作流仅监听 `main`，因此本地测试通过不等于 P1 分支已有云端 CI 结果；本批为测试工作流补充 `feat/**` 和 `codex/**` 分支触发。
